这份榜回答一个具体问题：这个项目我能不能直接塞进商业产品里。
不是「它的许可证叫什么」，而是「敢不敢上线」。所以每行给的是判定结论， 不是罗列许可证名字让你自己去查。

判定个数含义
不能商用8 AGPL 等强传染性协议，或明确禁止商业使用。必须改造或换替代
有传染性10 GPL 系。独立进程调用通常安全，链接进产品会把整个产品拖下水
无法判定8 仓库未声明许可证。法律上默认保留所有权利 —— 比 GPL 更麻烦
有条件33 MIT/Apache 为主，但要看清附加条款（商标、专利、署名）
可商用82结论明确，直接可用
40 个仓库没有可用许可证信息（占 28.4%）。 「没写许可证」不等于「随便用」—— 按伯尔尼公约，无许可证即默认保留所有权利， 商用前必须联系作者取得授权。这是比 GPL 更容易被忽略的坑。

怎么用这份榜

  1. 先看你的用法：只本地跑着玩，GPL 和 AGPL 都无所谓； 要嵌进卖给客户的产品，AGPL 基本等于禁止。
  2. 再看调用方式：AGPL 的触发条件是「通过网络提供服务」， 即使不分发代码，只要用户通过网络用了它，就得开源整个服务端。
  3. 最后看星数：星数高的项目诉讼风险也高，别指望「这么多人用应该没事」。

判定基于仓库 LICENSE 文件与 GitHub API 元数据，采样日期见各仓库最后提交时间。 许可证会变，上线前请自行复核最新版本。

本站数字均为真机实测，逐条标注验证等级（L1 多次复测取中位 / L0 单次测量）。查不到的写「未采集」，不估算。
