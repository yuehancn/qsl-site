MoE 专家库该放哪块盘：先反算命中率，别先买盘

环境与安装 · 3.932 MB（单专家单元，FP8）未标注整理于 2026-11-17 有效期 180d

MoE 推理每生成一个 token 都要把当轮选中的专家权重从存储读进来。Kolibri-1 781 亿参数里 96.7% 是专家，50 层每层 384 个专家、每 token 选 6 个，单专家 3.932MB，于是每 token 要读 1,179.6MB。同一份 7.39GB 分片按专家粒度随机读：本地 NVMe 6,106.60 MB/s、200G 环网取隔壁机器 2,194.51、本机 D 盘 2,181.90、1G 管理网 115.23、NAS 走 SMB 98.82。环网与本机第二块盘只差 0.58%，NAS 比本地慢 61.8 倍。把专家库放 NAS，要跑到 1 tok/s 就得 91.62% 命中，10 tok/s 要 99.16%，命中率高到等于没放。

具体做法

【实测口径】
  同一份 7,389,759,032 B 生产分片（model-00003-of-00048.safetensors）
  块大小 = 一个专家单元 3,932,160 参 x 1.0097 B = 3.932 MB
  100 次随机偏移，每档逐次校验 got == target，预热一次在计时区间外
  Linux 走 O_DIRECT，Windows 走 FILE_FLAG_NO_BUFFERING
【五位置吞吐（3.932 MB 块）】
  本地 DGX 板载 NVMe      6,106.60 MB/s   1,553.0 IOPS   p50 0.6031 ms   单专家 0.64 ms
  隔壁 DGX 经 200G 环网    2,194.51        558.1          1.7483           1.79
  本机 D 盘 NVMe       2,181.90        554.9          1.6249           1.80
  建筑机经 1G 管理网     115.23         29.3          34.0923          34.12
  NAS 经 SMB 1G          98.82         25.1          39.7725          39.79
  环网 vs 本机 D 盘 差 0.58%；NAS vs 本地 NVMe 慢 61.8 倍
【块放大到 5.625 MB 后的分叉】
  本地 6,106.60 到 7,547.59 (+23.6%)
  本机 D 盘 2,181.90 到 2,736.54 (+25.4%)
  环网 2,194.51 到 738.22 (-66.4%)   方向相反
  NAS 98.82 到 73.12 (-26.0%)
【命中率边界（每 token 1,179.6 MB）】
  目标 1 tok/s：  本地无需命中 / 环网无需 / 本机 D 盘无需 / 1G 90.23% / NAS 91.62%
  目标 5 tok/s：  环网 62.79% / 本机 D 盘 63.01% / 1G 98.05% / NAS 98.32%
  目标 10 tok/s： 本地 48.23% / 环网 81.40% / 本机 D 盘 81.50% / 1G 99.02% / NAS 99.16%
  目标 20 tok/s： 本地 74.12% / 环网 90.70% / 本机 D 盘 90.75% / 1G 99.51% / NAS 99.58%
【全 miss 时生成一个 token 要多久（300 个专家，纯 I/O 串行）】
  本地 193.2 ms / 环网 537.5 / 本机 D 盘 540.7 / 1G 10,237.3 / NAS 11,937.3
【KV 的另一面】
  Kolibri-1 50 层里只有 10 层随上下文长 KV（layer_types 的 full_attention，位置 4/9/14/.../49，每 5 层一个），40 层滑窗 513 封顶。262,144 上下文合计 5.039 GiB；50 层全长要 25.000 GiB，省 79.84%。省下的是显存，付的是每 token 1,179.6 MB 读盘，成本从显存挪到了盘。
失效边界
Kolibri-1 本体未下载未运行，本文零真实 tok/s。所有 tok/s 都是「每 token 1,179.6 MB 除以实测带宽」的上限，不含计算与 I/O 计算重叠，不是跑出来的速度。命中率 h 是参数化计算，不是实测路由分布：真实 MoE 路由有明显偏斜、热门专家会集中，实际命中率可能远高于均匀假设，本文只给「要达到目标速度需要多高命中率」，不给「实际能到多高」。5.625MB 块在环网上掉 66.4% 的成因未定位，未做 RTT 与 TCP 窗口与服务端 sendall 分片大小的梯度扫描，两种解释都不能排除。DGX #1 那组测试期间有 sglang 常驻（loadavg 3.38/2.43/1.88），本地绝对带宽偏保守，同机内部可比、跨机比较要打折。全部是单流 100 次串行，未测并发、未测 IO 与计算重叠。NAS 硬件规格未知（无 SSH，22 端口关闭），98.82 MB/s 无法归因到盘还是链路。只测了 DGX #2 一台远端。
