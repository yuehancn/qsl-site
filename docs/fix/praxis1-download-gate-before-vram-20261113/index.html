本地部署 Praxis-1 卡在 80GB 之前：真正拦住你的是 11.6 天

成本账 · 50.67 GiB（17 分片）/ 官方要求单卡 80GB未标注整理于 2026-11-13 有效期 180d

Praxis-1（27.2B MoE 世界动作模型，Apache-2.0）仓库实测 23 个文件 / 54,404,699,594 B = 50.67 GiB，切 17 个 safetensors，最大一片 4,992,798,140 B。官方模型卡要求单卡 80GB，本机最大单卡 5090D 是 32GB，差 48GB。但更早拦住你的不是显存：实测下载 53.1 KB/s，50.67 GiB 要下 11.6 天。两道门槛的顺序很重要——你连权重都拿不到手，纠结 48GB 缺口没有意义。

具体做法

【仓库体积自证（逐文件，镜像站 API）】
praxis-1-base：23 个文件 / 54,404,699,594 B = 50.67 GiB，17 个 safetensors
最大单片：4,992,798,140 B
praxis-1-droid（同家族变体）：54,404,890,103 B，比 base 多 190,509 B——差的正是动作头
license：Apache-2.0，参数量 27.2B MoE

【门槛一：下载（实测三段 22 秒窗口）】
53.1 KB/s / 52.9 KB/s / 33.8 KB/s
按 53 KB/s 折算，50.67 GiB 需 11.6 天
一台机器连续开 11.6 天不间断下载，中间不能断、不能限速、不能重启路由器。这不是「能不能跑」的问题，是「下载这件事本身就不成立」。

【门槛二：显存（官方要求单卡 80GB）】
RTX 5090D：32 GB，差 48 GB
DGX Spark（GB10 统一内存）：122 GB 整机，装得下，余 42 GB
4× 5060Ti：4 × 16 GB = 64 GB，差 16 GB，且要 4 卡并行

【为什么「装得下」不等于「该装」】
统一内存标称带宽 273 GB/s，实测 copy 512MB 在 225.9-233.6 GB/s 之间，达成率 85.6%。这个带宽对 27.2B 的 MoE 只够支撑很低的并行度。而这是世界动作模型，输入是视频帧序列不是聊天文本，对带宽的胃口和 LLM 完全不同。

【本文没有任何 Praxis-1 的推理数字】
本体未下载、未加载、未推理。原因是上面那 11.6 天。凡是我没跑过的，我不编。

失效边界
Praxis-1 本体未下载、未加载、未推理，零 tok/s、无加载耗时——本文所有与「跑起来多快」相关的判断都只是折算与推导，不是实测。显存缺口为算术推导（官方 80GB 要求减本机规格），不是实测 OOM。下载速率为三段 22 秒窗口的单次观测，受当时网络状况影响，不代表长期均值。50.67 GiB 与 54.4GB 是同一数字的二进制/十进制两种写法，不是两个数。「DGX Spark 装得下」只表示内存容量够，未验证能否真正加载与推理。
