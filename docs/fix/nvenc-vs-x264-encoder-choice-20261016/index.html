显卡编码反而更慢更大：nvenc 体积 2.44 倍只换回第五位小数的画质

性能 · 4 档编码器 / 116 秒正片L1整理于 2026-10-16 有效期 30d

同一段 116.4 秒正片四种编码参数各跑一遍：libx264 medium 2.40 秒 / 6,922,428 B，fast 2.27 秒 / 6,649,384 B，veryfast 2.16 秒 / 5,514,336 B，h264_nvenc -preset p4 3.47 秒 / 16,875,839 B。走显卡编码单元的 nvenc 同时输了速度和体积 —— 比 medium 慢 1.07 秒、体积 2.44 倍，而 SSIM 只高 0.000437。对照组里最划算的是 veryfast：体积砍 20.34%，代价 0.24 秒。

这条适用于

  • 同一份输入、同一码率档位下的编码器横向对照才成立
  • 体积与画质需在同一评价口径（SSIM/主观）下比

版本指纹

本机 5090D；nvenc 与 libx264 同输入对照（体积 2.44 倍 / 画质差在第五位小数）

具体做法

本机实测（2026-10-16，RTX 5090D 32GB；ffmpeg Lavc63.1.101）：

【四档对照（同一段 116.4 秒 / 768×1344@30fps 正片，各自完整跑一遍）】
· libx264 medium：2.40 s / 6,922,428 B / v码率 346,666 / SSIM 0.999259
· libx264 fast：2.27 s / 6,649,384 B / v码率 327,895 / SSIM 0.998847
· libx264 veryfast：2.16 s / 5,514,336 B / v码率 249,864 / SSIM 0.996752
· h264_nvenc -preset p4：3.47 s / 16,875,839 B / v码率 1,030,933 / SSIM 0.999696

【以 medium 为基准】
· fast：速度 1.06× / 体积 96.06% / SSIM 差 −0.000412
· veryfast：速度 1.11× / 体积 79.66% / SSIM 差 −0.002507
· nvenc：速度 0.68× / 体积 243.78% / SSIM 差 +0.000437

【nvenc 一次性初始化核查（同参数连跑 3 次）】
· nvenc：3.50 s / 3.47 s / 3.47 s（体积恒为 16,875,839 B）
· libx264 medium：2.40 s / 2.40 s / 2.41 s（体积恒为 6,922,428 B）
→ 无暗坑：nvenc 在这块卡上确实比 libx264 medium 慢。

【关键换算】
· 体积倍数 16,875,839 ÷ 6,922,428 = 2.4378（+143.8%）
· 用 2.44 倍码率换来的 SSIM 增量 = 0.999696 − 0.999259 = 0.000437（小数点后第四位）
· veryfast 相对 medium：体积 −20.34%，耗时 −0.24 秒（按 116 秒正片计，时间代价可忽略）
失效边界
本结论为本机实测（2026-10-16；RTX 5090D 32GB / ffmpeg Lavc63.1.101）。耗时为本机单次连续运行读数，同参数 3 次重复的极差在 0.03 秒以内；SSIM 为 ffmpeg 内置滤镜输出，仅用于同一批文件之间的相对比较。硬件编码与软件编码的压缩率差异会随源素材复杂度、分辨率和码率目标变化，本文数值为 768×1344 屏采画布上的结果，换分辨率请自行复测。测量前已停止本机其他占卡任务。
