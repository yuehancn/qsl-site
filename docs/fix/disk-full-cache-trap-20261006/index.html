C 盘突然爆满：模型没存 C 盘，但缓存全在 C 盘

环境与安装 · 5 个环境变量 / 10 分钟L1整理于 2026-10-06 有效期 permanent

明明把模型都放在了 D 盘，C 盘却一天掉几十 G —— 因为 pip 缓存、HuggingFace 缓存、torch 下载、Docker 镜像、以及各类 appdata 默认都写在 C 盘用户目录。报错出现在 SystemDrive 有空间，报错的路径却在 C:\Users\...。修法不是删文件，而是把这几类缓存目录用环境变量统一迁到数据盘，一劳永逸。

排错磁盘缓存环境变量工程实践

这条适用于

  • 模型已按约定放非系统盘
  • 但系统盘（C）仍突然爆满

版本指纹

Windows 11；环境变量名 HF_HOME / MODELSCOPE_CACHE / TORCH_HOME / OLLAMA_MODELS / PIP_CACHE_DIR

具体做法

—— ① 先查谁在吃 C 盘 ——

Windows：用 WizTree / SpaceSniffer（比资源管理器快百倍）
Linux：du -sh /* 2>/dev/null | sort -h

# —— ② 把各类缓存一律迁出 C 盘（本机约定：模型一律 D:\models）——
# HuggingFace
setx HF_HOME                      D:\models\huggingface
setx HUGGINGFACE_HUB_CACHE        D:\models\huggingface\hub
# ModelScope
setx MODELSCOPE_CACHE             D:\models\modelscope
# Torch / torchvision 预训练权重
setx TORCH_HOME                   D:\models\torch
# Ollama 模型
setx OLLAMA_MODELS                D:\models\ollama
# pip 下载缓存（这个最容易忽略，动辄十几 G）
setx PIP_CACHE_DIR                D:\models\pip-cache
# —— ③ 立即清一次历史缓存 ——
$ pip cache purge
$ python -c "from huggingface_hub import scan_cache_dir as s; print(s())"
$ docker system prune -a            # ⚠️ 会删未使用的镜像/卷，先确认
# —— ④ 验证 ——
$ echo %HF_HOME%                    # 应输出 D:\models\huggingface
失效边界
适用边界：本机实测环境为 Windows 11，已定「软件装 C 盘、模型一律 D:\models」的约定；下面的环境变量名（HF_HOME / MODELSCOPE_CACHE / TORCH_HOME / OLLAMA_MODELS / PIP_CACHE_DIR）为各框架官方变量名，跨平台通用。两个提醒：① 迁目录前先把旧缓存删掉或移走，否则只是新缓存不落 C 盘、旧空间没释放；② docker system prune 会删除未被任何容器引用的镜像与卷，执行前务必确认没有需要的镜像。
