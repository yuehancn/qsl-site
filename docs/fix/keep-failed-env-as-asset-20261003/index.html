装废的环境别急着删：把失败原因抄成一行，比留着几个 GB 值钱

工程习惯 · 1 步 / 30 秒L1整理于 2026-10-03 有效期 permanent

跑不通的旧项目是成本最低的环境资产。删掉只省几个 GB，丢掉的是「什么会坏」的真实记录。做法只有一步：删之前把「什么操作 + 什么报错 + 真实原因」抄成一行放固定地方，抄完就随便删。失败的记录比成功的记录信息量更大，因为成功有很多条路，失败会精确告诉你哪条不通。

Python环境排障工程实践开发习惯知识管理

这条适用于

  • 环境已判定为「装废」（准备删除）
  • 愿意在删除前花两分钟导出记录

版本指纹

本机个人记录量 40+ 条 / 三个月（非通用规模）

具体做法

【反直觉对比】
删掉旧项目 → 只有「看起来干净」的主环境 → 遇到新问题从零试错
留着旧项目 → 能翻出三四种「已知会坏」的配置 → 半小时内定位到问题类型
差别不在硬盘，在「面对未知故障时的起点」

【记录格式】
[日期] 操作 → 报错原文 → 真实原因

一条真实例子：
「python -m pip -V 报的版本号，跟实际跑程序的那个解释器不是同一个」
→ 对着这条记录，两分钟确认了「多 Python 环境静默错配」问题类型

【为什么失败记录更值钱】
「干净」不等于「安全」：没出过问题的环境，你只知道它能用，
不知道它在什么条件下不能用。坏过的环境边界是画出来的——
知道改哪行会崩、哪个依赖版本不能动、报错长什么样。
这些边界信息只能通过失败获得。

【命中率】本机记录文件 40+ 条，新报错先搜它，命中率约三成
—— 这三成就是把从零排查变成半小时排查的部分。

失效边界
「命中率约三成」「两分钟定位」为个人主观计时与估计，非精确测量，实际随问题熟悉程度变化。「40+ 条 / 三个月」是本机个人记录量，不代表通用规模。
