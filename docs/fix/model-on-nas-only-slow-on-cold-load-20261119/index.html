模型放 NAS 只慢在冷加载：载入内存后出字速度和本地盘一样

环境与安装 · 553 MiB / 10.3 倍冷加载差 / decode 无差 / 加载方式极差 2.7%未标注整理于 2026-11-19 有效期 permanent

同一份 553 MiB 的 Qwen3.5-0.8B Q4_K_M、同一台机器、同一个 llama-bench，只改模型放哪块盘：冷加载本机 D: NVMe 0.606 秒，NAS（SMB / 1G 链路）6.243 秒，本地快 10.3 倍。但载入之后，decode 是 76.37 对 77.34 tok/s —— 差 1.3%，落在误差里；prefill 甚至 NAS 反高 11%（864.29 对 961.80）。第二次跑（文件已在 page cache）两者变成 0.600 对 0.559，倍数掉到 1.07，等于没有差别。

NAS模型存储冷加载本地部署llama.cpp1G链路加载方式选型

这条适用于

  • Qwen3.5-0.8B Q4_K_M GGUF（579,615,840 B）+ llama-bench build 11901 或更新（-lm 已取代 --no-mmap）
  • NAS 需 SMB 可写；1G 链路实测 105.78 MB/s 上限
  • 冷加载须用全新文件，否则 page cache 会抹掉倍数

版本指纹

llama-bench-11901/qwen35-0.8b-q4km/1g-smb

具体做法

【实测口径】
  机器：RTX 5090D 32GB / Intel Core Ultra 7 270K Plus 24 核 / 98GB
  模型：Qwen3.5-0.8B Q4_K_M，579,615,840 B（Q4_K_M + mmproj 已下齐）
  二进制：llama-bench build 11901 / commit 5320c87ff（version 0.7.0-dev）
  参数：-t 8，冷加载为全新文件（非 drop_caches，无 root 权限）
  介质：本机 D: NVMe（INTEL SSDPF2KX019T1M）/ NAS 经 SMB，1G 链路

【冷加载，2 轮】本机 0.607 / 0.605（中位 0.606 s）｜NAS 6.529 / 5.956（中位 6.243 s）→ 10.3×
【进程墙钟首次】本机 0.603 s ｜ NAS 6.117 s → 10.1×
【第二次（page cache 已热）】本机 0.600 s ｜ NAS 0.559 s → 1.07×
【pp128 prefill】本机 864.29 ± 34.74 ｜ NAS 961.80 ± 21.05 t/s → 1.11×（NAS 反高）
【tg32 decode】本机 76.37 ± 0.97 ｜ NAS 77.34 ± 0.29 t/s → 1.01×（无差别）

【加载方式四档（同 D 盘文件）】mmap 909.07/79.08 ｜ none 852.56/78.94 ｜ dio 848.24/81.06 ｜ mlock 914.15/79.76
  极差 2.7%（78.94-81.06）→ -lm 只影响冷启动与内存占用，不影响出字
  注：新版 llama.cpp 已移除 --no-mmap，改为 -lm / --load-mode
失效边界
NAS 硬件规格未测到（22 端口关闭，无法 SSH）。105.78 MB/s 的上限来自 1G 链路（0.95 Gbps 的 85-95%），不是盘的极限。2.5G / 10G 链路、SMB 多通道、NFS 全未测 —— 换成 2.5G 以上，这组倍数会明显缩小。冷加载用的是「全新文件」口径，不是 drop_caches 等价方案（本机与 ARM 工作站均拿不到 root）。0.8B 只测了 8 线程一档，未做线程梯度。
