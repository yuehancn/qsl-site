pip 装成功了程序还是缺包：多 Python 环境的静默错配

环境与安装 · 1 条命令判据 / 5 张对照表L1整理于 2026-10-01 有效期 30d

pip 返回 Successfully installed、import 也真的通，程序还是报 ModuleNotFoundError —— 因为机器上同时活着三套 Python。pip 与 python 命中的解释器由 PATH + Windows App Execution Aliases 决定，与你想装到哪无关；venv 又设了 include-system-site-packages = false，base 装了也读不到。两层失败方式完全相同：成功、无报错、程序看不见。唯一判据：跑 pip -V，看末尾括号里的解释器路径。

ComfyUIPython环境依赖管理排错Windows

这条适用于

  • 机器上同时存在多套 Python 解释器（PATH + App Execution Aliases 共同决定用哪套）
  • 程序跑在 venv 里（venv 默认 include-system-site-packages=false）

版本指纹

Windows 11 + RTX 5090D；三套 Python（3.12.10 裸 / 3.12.10 venv / 3.13.12 托管）；cu128 + torch 2.11.0

具体做法

实测环境：Windows 11 + RTX 5090D，2026-10-01

本机三套 Python（互不可见）

① C://AI//PY//tools//python.exe 3.12.10 无 torch 两个 venv 的 base
② C://AI//ComfyUI//venv//Scripts//python.exe 3.12.10 torch 2.11.0+cu128 ComfyUI 真实运行环境
③ ...\binaries\python\versions\3.13.12\python.exe 3.13.12 无 torch 裸 python / pip 默认解析

# 决定性判据：两条 pip -V，两个答案
$ python -m pip -V
# pip 26.1.2 from ...\3.13.12\Lib\site-packages\pip (python 3.13)   <- 装到 ③
$ C://AI//ComfyUI//venv//Scripts//python.exe -m pip -V
# pip 25.0.1 from C://AI//ComfyUI//venv//Lib//site-packages//pip (python 3.12)   <- 装到 ②，这才是对的
# 为什么带 base 路径装也没用：
$ cat C://AI//ComfyUI//venv//pyvenv.cfg
# home = C://AI//PY//tools
# include-system-site-packages = false   <- 明确声明不看 base 的包

四种装包姿势，只有最后一种有效

pip install X -> 默认解析的环境 ✗
python -m pip install X -> 同上 ✗
<base>\python.exe -m pip install X -> base site-packages ✗
<程序venv>\Scripts\python.exe -m pip install X -> 程序自己的环境 ✓ 唯一正确

为什么这个坑藏得久：启动脚本写死了 venv\Scripts\python.exe（对），

装包走 PATH 上的裸 python（错）。启动每天做，装包几周才做一次 —— 低频操作不形成肌肉记忆。

顺手查出：同一台机器三个 ComfyUI 前端版本

真跑 venv 1.49.6 / 托管 venv 1.51.9 / 上游要求 1.53.6
五组依赖落差：workflow-templates 落后 15 补丁、comfy-aimdo 落后 8 个小版本、comfy-kitchen 落后 5 补丁
后果：报 bug 填哪个版本号，取决于你从哪个终端复制

另有一条软性偏差：上游 README 要求 20 系以上用 cu130+，本机实为 torch 2.11.0+cu128

目前是「声明的」而非「强校验的」，实测出图正常 —— 记进环境档案让它可见，不当场升级产线。

一句话：最贵的报错不是「装不上」，是「装上了但没人看见」。

失效边界
适用边界：核心判据（用哪个解释器跑、就用哪个解释器装）在所有 Python 环境通用；但三套环境的路径、版本号与 pyvenv.cfg 均为 2026-10-01 本机实测值，换机/换安装顺序即变。两个易踩点：① 三个前端版本（1.49.6/1.51.9/1.53.6）是当日快照，上游滚动发布，几天后失效，不要当固定事实引用；② cu130 口径来自上游 README，属声明性要求，本机 cu128 实测正常 —— 不要据此当场重建环境。
