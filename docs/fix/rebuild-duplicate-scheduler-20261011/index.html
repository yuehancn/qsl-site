又搭了一遍调度，那台机器上早跑着两个：自建前先查账

工程习惯 · 7 步 / 15 分钟L1整理于 2026-10-11 有效期 permanent

准备从零搭一套内容调度，列完清单才去查那台该干活的机器 —— 上面早有两个已激活的工作流、四个脚本和一整套台账表。自己清单里的八项功能，七项与它完全重复，剩下一项是它做了而自己没打算做的。正解不是重写，是桥接：只写一层转发，不重写选机、质检、记账逻辑。

这条适用于

  • 准备自建一套调度或编排
  • 目标机器此前可能已被他人部署过系统

版本指纹

本机内容工厂 + 局域网调度机实际部署（2026-10-10）

具体做法

实测盘点（本机内容工厂，2026-10-10 对局域网调度机实际查证）：

它已经在跑的：
· 2 个已激活工作流：农场巡检（健康检查与台账）、农场出图调度（批量生成落网盘）
· 4 个脚本：巡检（SSH + nvidia-smi）、出图调度器（智能选机 / 提交 / 轮询 / 收图 / 记账 / 质检）、健康告警（含 Wake-on-LAN 自动唤醒）、出图质检（查黑图 / 纯色 / 无结构）
· 5 张台账表：巡检台账 / 告警记录 / 出图任务记账 / 批次记账 / 服务与定时任务

自己准备写的清单 → 对照结果：
· 出图节点选择 → 重复
· 提交 / 轮询 → 重复
· 收图落网盘 → 重复
· 出图质检 → 重复
· 出图记账 → 重复
· 健康巡检 → 重复
· 故障告警 → 重复
· 掉线自动唤醒 → 重复，且自己原本没规划
=> 8 项里 7 项完全重复，1 项是对方做了、自己没打算做的

改法：
· 调度器降级为「桥接」：ssh 调用既有出图脚本，不碰选机/质检/记账/告警
· 编排放调度节点，本机只做生产（也不要在本机另起一套编排）
· 结果：省掉整整一套调度/质检/记账/告警代码，也省掉日后「两套台账对不上」的麻烦

失效边界
本条目是「查证 + 判断」型经验，不是可直接复制的命令；结论依赖该局域网既有系统的实际部署。若目标机器确实为空，或既有系统已停用/不满足需求，则自建是合理选择，本条不适用。判断「重复/不重复」是主观对照自身实现清单得出，非官方结论。
