同一套产线的成片体积差 1.7 倍：稳的那条被写死了，飘的那条没写

成本账 · 7 步 / 15 分钟L1整理于 2026-10-10 有效期 180d

同一台机器、同一个人做的片子，时长几乎一样，体积却差 1.7 倍。拆开两条流就清楚了：视频码率极差 6 倍，音频码率极差只有 1.09 倍。差异全在「编码参数有没有显式写死」上。体积不是能管理的量，它是参数缺省后的结果。

FFmpeg码率CRF成片体积压缩编解码成本核算

这条适用于

  • 同一套产线成片体积波动大
  • 需要把「体积可预算」这件事变成可控项

版本指纹

本机成片产线（2026-10-10）；CRF 观感须按自己素材目视标定

具体做法

诊断命令（只读视频流那一条码率）：
ffprobe -v error -select_streams v:0 \
  -show_entries stream=bit_rate -of csv=p=0 "你的片子.mp4"

只看音频：把 v:0 换成 a:0。

实测（47 条已发布成片，同一套产线）：
· 时长 78.4 ~ 154.8 秒（均值 113.0）
· 体积 5.51 ~ 21.92 MB（均值 12.11）
· 视频码率 256 ~ 1536 kbps → 极差 6.00 倍
· 音频码率 105 ~ 114 kbps → 极差 1.09 倍
· 音频占体积 6.7% ~ 30.7%（均值 15.9%）

控制时长后的对照（85~95 秒区间，6 条）：
· AI一人公司 90.5s / 9.23MB / 视频 695k / 音频 112k
· AI味产线 92.0s / 13.50MB / 视频 1055k / 音频 111k
· 绘本产线 86.4s / 14.43MB / 视频 1219k / 音频 109k
· 就绪探针 88.0s / 14.80MB / 视频 1224k / 音频 112k
· pip装错环境 92.1s / 15.77MB / 视频 1251k / 音频 110k
· 大模型硬件选型 85.6s / 16.01MB / 视频 1381k / 音频 107k
→ 时长极差仅 7.6%，体积极差 1.74 倍；差异全在视频码率（695k → 1381k，1.99 倍）

归因：
· 音频稳不是因为控住了，是因为混流里写了 -c:a aac 却没写 -b:a，AAC 默认码率按采样率与声道数推导；本机素材恰是全 44100Hz 立体声，输入条件太整齐，默认值每次都撞到同一位置。换 48kHz 或单声道，这个「稳定」立刻不成立。
· 视频飘是因为走 libx264 且没显式指定 -crf 或 -b:v，走的是内容自适应码率分配：画面动得多就给得多，静止深底讲解帧就抠着给。同一个「90 秒 768×1344 30fps」能差一倍。

失效边界
「码率极差大」本身不等于画质有问题 —— 内容自适应分配是编码器的正常设计，本条目只指出它让体积变得不可预算。锁 CRF 之后体积仍会飘（这是质量优先的必然代价），只是飘的原因从「随机」变成「可解释」。不同 CRF 值对应的观感需按自己的素材目视标定，本条目未给出 CRF 取值建议。若发布平台的推荐码率区间有硬要求（如上限），应改锁码率并在复杂画面上接受观感损失。
