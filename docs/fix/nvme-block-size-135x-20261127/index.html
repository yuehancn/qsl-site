同一块盘读速差 135 倍：本地部署前先量这两档块大小

排障 · 同一块盘读速差 135 倍：本地部署前先量这两档块大小未标注整理于 2026-11-27 有效期 permanent

同一块 DGX Spark 的 NVMe、同一个 6.88 GiB 权重分片、同一个脚本，只把每次读的大小从 4 KB 改成 1 MB，读速从 **16.62 MB/s 变成 2,245.17 MB/s，差 135.1 倍**（Spark #2 复现 133.9 倍）。工程含义：**盘本身够快，默认参数下你只拿到 0.74%**。这条对按需从盘搬权重的模型（Strata/offload 类）是生死线——125.73 GiB 的权重冷加载，4 KB 档要 **2.2 小时**，1 MB 档只要 **11.8 秒**。第二个坑：加线程能换聚合吞吐（六流 9.80 GB/s，涨 3.35 倍），但**每流掉 44%**，单请求加线程只会一起排队。

具体做法

Spark 侧单流值受同机 sglang 常驻影响，两轮离差 14.9%，正文已标注；135 倍的比值建立在两台同型机上（135.1 / 133.9），但，未测 4 MB/16 MB 等更大档，因此不能断言 1 MB 是最优点。Mac mini 侧数字（4 KB 3,999 MB/s / 1 MB 11,199 MB/s）来自另一台不在本机 16 台清单里的机器，只作跨架构对照，未挂跑分表。
