买卡前先反算每参字节：按 BF16 估会白买三张 32G 卡

成本账 · 78.86 GB（FP8 权重）/ 5.41 GB（KV）/ 84.27 GB（合计）未标注整理于 2026-11-17 有效期 180d

同一个 MoE 模型在三个仓库里的体积差 16.4 倍，而决定买几张卡的是「每参字节」这一个数。Kolibri-1 官方权重 78,862,325,722 B 除以 781.03 亿参 = 1.0097 字节每参，是 FP8；BF16 仓 156,228,415,946 B = 2.0003；GGUF 仓 87 个文件合计 1.29 TB，是官方 FP8 的 16.4 倍。加 5.41 GB 的 KV 后，FP8 要 84.27 GB（3 张 32G，余 11.73），BF16 要 161.64 GB（6 张，余 30.36）。单卡 32G 分别差 52.27 GB 与 129.64 GB。

MoE选型显存量化本地部署买卡位宽大模型预算

这条适用于

  • 目标模型的官方仓库名，以及能访问 hf-mirror API 的网络
  • 目标模型的 config.json（层数 / hidden_size / moe_intermediate_size / KV 头数 / head_dim）
  • 你知道自己有哪种卡、单卡多大显存

版本指纹

Kolibri-1 三仓库体积 / config 原值 / 2026-11-17

具体做法

【三个仓库（hf-mirror API 逐文件 size 求和）】
  Aleph-Alpha/Kolibri-1          40 文件   78,862,325,722 B   78.86 GB   1.0097 字节每参
  Aleph-Alpha/Kolibri-1-BF16     40 文件  156,228,415,946 B  156.23 GB   2.0003 字节每参
  bartowski/Kolibri-1-GGUF       87 文件 1,292,009,949,308 B    1.29 TB   (FP8 的 16.4 倍)
【GGUF 单档字节】
  Q4_K_L  53.514 GB
  Q4_K_M  49.759 GB
【KV（按 config 逐层算，fp16，K 与 V 各一份）】
  每层每 token = 2 x 4 KV头 x 128 head_dim x 2 B = 2,048 B
  全注意力 10 层 @ 262,144 = 5.000 GiB；滑窗 40 层封顶 513 = 0.039 GiB；合计 5.039 GiB = 5.41 GB
  反事实（50 层全长大 KV）= 25.000 GiB，省 79.84%
  ctx 阶梯：4,096 = 0.117 GiB / 32,768 = 0.664 / 131,072 = 2.539 / 262,144 = 5.039
【卡数（向上取整，未含运行时开销）】
  32G 卡：FP8 78.86+5.41=84.27 GB 得 3 张 余 11.73
         BF16 156.23+5.41=161.64 GB 得 6 张 余 30.36
  24G 卡 FP8 4 张 / BF16 7 张
  48G 卡 FP8 2 张 / BF16 4 张
  单张 32G 差：FP8 52.27 GB / BF16 129.64 GB
  Q4_K_M 49.759 GB 塞 32G 仍差 17.76 GB，得 2 张
【结构（config.json 原值）】
  num_hidden_layers 50 / hidden_size 2560 / num_attention_heads 48 / num_key_value_heads 4 / head_dim 128
  num_experts 384 / num_experts_per_tok 6 / moe_intermediate_size 512 / max_position_embeddings 262144
  layer_types 50 项，full_attention 恰好 10 层
失效边界
本文不含任何模型加载或推理，全部是「仓库字节数 加 参数量 加 config 层结构」的算术值，因此没有 tok/s、没有显存占用实测。卡数是「向上取整」的下界，未计入运行时开销（显存碎片、CUDA context、激活值）与不同推理框架的显存管理策略，实际可装张数可能更保守。KV 按 fp16 逐层计算，未做 KV 量化对照。Q4_K_M 与 Q4_K_L 的字节数取自仓库 size 字段，未下载核对。
