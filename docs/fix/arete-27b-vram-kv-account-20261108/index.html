具体做法

混合注意力模型的宣传点通常是「省显存」。这个说法对一半。

省的是上下文那部分的增长斜率。Arete-27B 的 64 层里 48 层是线性注意力，不按上下文长度存 KV，所以每 token 只要 64 KiB，而不是全 64 层口径的 256 KiB。256K 上下文从 64 GiB 降到 16 GiB，这个 4 倍是真的。

但权重一分没省。27.36B 参数在 BF16 下就是 54.74 GB，能压到 17.20 GB 靠的是量化，跟注意力结构毫无关系。所以对 16G 卡用户来说，它的友好程度和任何一个 27B 稠密模型一样：都装不下。

真正兑现那 4 倍的前提是「你已经有足够显存」。一张 32G 卡跑 Q4_K_M，普通 27B 全注意力模型要 64 GiB KV 直接出局，Arete 只要 16 GiB 塞得进去。这就像「这车很省油」—— 前提是你先买得起这车。

失效边界
① 权重体积与各档字节来自仓库 API 真源，层结构来自官方 config 原文；② KV 体积与各卡可开上下文全部是算术推导，不是实测运行 —— Arete-27B 本体未下载未加载；③ 统一扣 1 GiB 作为激活与计算图预留，这是工程惯例取值，不同推理框架实际开销不同，真实可开上下文会低于本文推算；④ 4090 的 24G 为标称值，该卡不在本站测试床内，仅作对照；⑤ 名义位宽与实际位宽差异（Q4 标 4 bit 实际 5.03 bit）是 GGUF 的 K-quant 混精度结构决定的，不是哪个转换脚本算错。
