本地部署大模型要多少显存：权重只是首付，KV 才是月供

环境与安装 · 61.69 GiB bf16 / KV 208 KiB 每token / 七档零差值 / 512K=104 GiB / 16G 卡 6-24 档L1整理于 2026-10-27 有效期 180d

算显存只算权重的结果一定会崩。真实账单 = 权重 + KV 缓存 + 固定开销。以 Nanbeige4.3-33B（33B 稠密）为例：bf16 权重 66,238,009,168 B = 61.69 GiB；KV 每 token = 2×52层×8头×128维×2字节 = 212,992 B（208 KiB），512K 满上下文要 106,496 MiB = 104 GiB；再加计算缓冲约 207 MiB。8K 上下文下 16G 卡总账 11,776 MiB、32G 卡占 36.1%，而 16G 卡的天花板是 29.8K token —— 32K 就差 461 MiB 装不下。

本地部署显存KV缓存量化选卡大模型16G24G32GGGUF

这条适用于

  • 能读到模型官方 config.json 的 num_hidden_layers / num_key_value_heads / head_dim
  • llama.cpp 或其他支持打印 KV buffer size 的运行时（用于验证公式）
  • memory.total 用 nvidia-smi 读实际值，不要用产品标称的 16G/24G/32G

具体做法

本机实测环境：Windows 11 / llama.cpp b11901（commit 5320c87ff）/ CPU 后端（-ngl 0）/ Nanbeige4.3-33B-IQ2_XXS.gguf 10,071,403,648 B。

【权重】
· 官方 14 个 safetensors 分片合计 66,238,009,168 B = 61.689 GiB = 66.238 GB
· GGUF 头部解析：471 张量 / 46 个 KV 对 / 元素合计 33,118,977,024 = 33.119B；平均 16.000 bit/参数
· IQ2_XXS 档 10,071,403,648 B = 9.387 GiB；与 bf16 相差 6.577 倍，参数量不变

【结构拆解（IQ2_XXS 471 张量）】
· 前馈 ffn 6.245 GiB（66.53%）/ 注意力 attn 1.897 GiB（20.21%）/ 词表 1.245 GiB（13.26%）
· 词表两个矩阵：token_embd Q3_K 3.44 bit（490.3 MiB）+ output Q5_K 5.50 bit（784.4 MiB）
· 去词表后 30.726B 参数平均仅 2.276 bit，全文 2.435 bit —— 词表被刻意保住

【KV（官方 config：52 层 / 8 KV 头 / head_dim 128）】
· 每 token = 2×52×8×128×2 = 212,992 B = 208.0 KiB
· 实测（CPU KV buffer size）：2048→416.00 / 8192→1664.00 / 16384→3328.00 / 32768→6656.00 / 65536→13312.00 / 131072→26624.00 / 262144→53248.00 MiB
· 与公式七档零差值；512K 推算 106,496 MiB = 104 GiB
【内存分解表（8K 上下文）】
· Host 11464 MiB = model 9593 + context 1664 + compute 207
· mmap 三段 1468.39 + 181.37 + 7943.39 = 9593.15 MiB，文件实际 9604.84 MiB，差 11.69 MiB（GGUF 头与 32 字节对齐）

【24 档账单（权重 + 8K KV 1664 + 固定开销 507）】
· 5090D（32607 MiB）：23/24 装得下，唯一越界 Q8_0 超 3,129 MiB
· 5060Ti（16311 MiB）：6/24 装得下（IQ2_XXS/XS/S/M、Q2_K、IQ3_XXS）；第一越界 Q3_K_S 超 367 MiB
· DGX Spark（123904 MiB）：24/24

【上下文天花板】
· 5090D + IQ2_XXS：可用 KV 22495 MiB → 108.1K token
· 5060Ti + IQ2_XXS：可用 KV 6199 MiB → 29.8K token（32K 差 461 MiB）
· CPU 实测 decode 8.1/8.3/8.3 t/s，prefill 48.3/46.0/48.7 t/s（三轮，-c 8192 -n 64）

失效边界
四条边界：① KV 按 fp16 计算，用 KV 量化（q8_0 / q4_0）实际占用会更低，本文数字是上限 ② 固定开销里的 CUDA 上下文（约 300 MiB）是估值不是实测，本机只有 CPU 后端可测 ③ 计算缓冲 207 MiB 是 llama.cpp 8K 上下文的值，上下文越长它也会变（注意力矩阵随长度增长），不能当常数 ④ 上下文天花板（108.1K / 29.8K）是按权重加 KV 加固定开销不超过 memory.total 算的账面值，实际还要留推理时的临时张量，真实可用会比这个少一些。
