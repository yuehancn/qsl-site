模型文件先读头再加载：260 KB 看清 1438 个张量，别让加载器替你全读 16 GiB

排障 · 260 KB · 5,671× · 省 36.7%L0整理于 2026-10-21 有效期 30d

safetensors 的文件结构是「8 字节头长度 + 一段 JSON + 权重数据」，JSON 里写明每个张量的名字、形状、精度和字节偏移。所以想查清一个模型到底装了什么、精度是不是它标的那样、值不值得重下，只需要读那一段 JSON，不用碰权重。本机实测：FLUX schnell fp8 单文件 16.05 GiB，头仅 260,000 字节（占 0.0015%），读头 0.96 毫秒，读全量 5.46 秒，比值 5,671 倍；最极端的是 minimax_h3 int8（19.53 GiB，头仅 95,416 字节），比值 16,302 倍。反过来，ComfyUI 0.33.0 的 UNETLoader 走 load_diffusion_model → load_torch_file，用 `for k in f.keys()` 无过滤把整个打包文件全读进内存——FLUX 那 1438 个张量里只有 776 个（model.diffusion_model，11.07 GiB）真正参与建模，另外 418 个 text_encoders（4.67 GiB）与 244 个 vae（319.75 MiB）读进来就被前缀过滤扔了。只读 UNet 段 vs 全量：FLUX 省 36.7%、SDXL 省 27.6%；但 Wan2.2 三个纯 UNet 文件为 3.1% / −2.0% / −1.7%（无收益）——读放大只在「把不相干的东西打进同一个文件」时才发生。

版本指纹

ComfyUI 0.33.0；D:\models 57 个权重文件；RTX 5090D 32GB / D 盘 NVMe / Windows 11

具体做法

环境：本机 RTX 5090D 32GB / D 盘 NVMe / Windows 11 / ComfyUI 0.33.0，2026-10-21。测量方式：每个文件读头 7 次取中位、读全量 3 次取中位；文件均已在系统页缓存中，故该组数字反映「已缓存后的解析开销」，不是冷盘首读（冷盘会更慢，但比值方向一致）。

失效边界
本结论为本机实测（2026-10-21；RTX 5090D / D 盘 NVMe / ComfyUI 0.33.0）。读头与读全量耗时均在文件已进入系统页缓存的条件下测得，代表解析开销而非冷盘首读。只读 UNet 段实验用绝对偏移直接 seek 读取，跳过了非 UNet 张量，因此负收益档位（Wan2.2 三个）的差异来自多次 seek 的额外开销，属测量误差量级，不代表「分开读更慢」的结论。本文只讨论文件结构、读取量与内存占用，不含任何画质或生成质量判断。T5 词表两份是否逐字节相同未做全量比对（1.3 亿字节），故只用「很可能相同」表述。
