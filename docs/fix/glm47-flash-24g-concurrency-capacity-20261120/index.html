GLM-4.7-Flash 显存账：24G 卡权重装得下，但只能跑一路

成本账 · 1 个模型 / 4 档上下文 / 3 张卡未标注整理于 2026-11-20 有效期 permanent

GLM-4.7-Flash 的 Q4_K_M 是 18,474,983,296 字节（17.2 GiB），名义 4 bit 实际 4.734 bit 每参，多吃 18.3%。它用 MLA 结构，每层每 token 只缓存 576 个数（kv_lora_rank 512 + qk_rope_head_dim 64），4,096 上下文只要 0.207 GiB，131,072 要 6.609 GiB，config 上限 202,752 要 10.224 GiB，FP8 减半。能不能开第二路取决于「可用显存 − 权重」还剩多少：24G 卡可用约 23.2 GiB，减掉 17.2 剩 6.0 GiB，而一路 128K 要 6.6 GiB，差 0.6 GiB，结果是 0 路而不是 1 路；32G 卡剩 14.0 GiB 能开 2 路；48G 卡剩 29.8 GiB 能开 4 路。想用 24G 卡就必须把上下文砍到 96K（缓存 4.94 GiB）以下。

具体做法

【体积账（仓库 API 逐文件直读，2026-11-19 现查）】
  zai-org/GLM-4.7-Flash 本体仓：58 文件 / 62,465,286,500 B = 62.47 GB，safetensors.total = 31,221,488,576 参 → 2.0007 字节每参
  bartowski/zai-org_GLM-4.7-Flash-GGUF：31 文件 / 483,605,487,876 B = 483.61 GB（本体 BF16 的 7.74 倍）
  Q4_K_M 18,474,983,296 B（18.475 GB / 17.2 GiB）
  Q5_K_M 21,566,252,928 B ｜ Q6_K_L 24,979,492,736 B ｜ Q8_0 31,842,799,488 B ｜ bf16 双片 39,745,402,368 B
  实际位宽：18,474,983,296 × 8 ÷ 31,221,488,576 = 4.734 bit 每参（名义 4 bit，多吃 18.3%）

【config 原值】num_hidden_layers 47 ｜ kv_lora_rank 512 ｜ qk_rope_head_dim 64 ｜ qk_nope_head_dim 192 ｜ v_head_dim 256 ｜ n_routed_experts 64 ｜ num_experts_per_tok 4 ｜ max_position_embeddings 202,752 ｜ vocab_size 154,880 ｜ model_type glm4_moe_lite

【MLA 的 KV（按 config 逐层算术，非 RSS 实测；每层每 token 576 数 = 1,152 B FP16）】
  4,096 → 0.207 GiB FP16 / 0.103 GiB FP8
  32,768 → 1.652 / 0.826
  131,072 → 6.609 / 3.305
  202,752（config 上限）→ 10.224 / 5.112
【三张卡的真实答案】
  24G（可用约 23.2 GiB）：减权重剩 6.0 GiB，差 0.6 GiB → 0 路 128K
  32G（约 31.2 GiB）：剩 14.0 GiB → 2 路（用 13.2，余 0.8）
  48G（约 47.0 GiB）：剩 29.8 GiB → 4 路（用 26.4，余 3.4）
  24G 砍到 96K 上下文：缓存 4.94 GiB → 刚好 1 路

【容量口径提醒】媒体口径写「128K」，config 原值 202,752，两个数不一致，本方案以 config 原值为准。

失效边界
KV 体积是按 config 逐层算术推得，不是 RSS 阶梯实测；同族结构在别的模型上「算得 vs 量得」比值曾达 1.004，但那是另一套注意力结构，不能直接外推。三张卡的可用显存是标称值扣驱动开销的估算（24G 按 23.2 / 32G 按 31.2 / 48G 按 47.0），未在本机实测 nvidia-smi，实际会浮动，缺口 0.6 GiB 这种量级的判断需要在真机上复核。层数口径有分歧：config 写 47 层、含首层稠密层，本方按 44 层注意力层算，口径差异会让 KV 数浮动 5% 左右。GLM-4.7-Flash 本体未下载未运行，本方案不含任何 tok/s 数据，并发路数也没有实跑验证，是纯容量算术。价格未写死数，需按发版当天行情自算。
