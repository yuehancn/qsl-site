Ollama 局域网访问怎么通：三道门 + 2.16 秒启动空窗

环境与安装 · 3 道门 / 17+1 条来源 / 0 条防火墙规则 / 2.16 秒空窗未标注整理于 2026-10-26 有效期 180d

Ollama 从「本机能用」到「别的机器能用」要过三层完全不同的检查：应用层绑定地址（OLLAMA_HOST，默认只听 127.0.0.1）、程序层来源白名单（OLLAMA_ORIGINS，默认 17 条全是本机与编辑器协议，命中时返回 403 且响应体长度为 0）、系统层防火墙程序规则（Windows 上 ollama.exe 入站放行规则 0 条，python.exe 是 4 条）。此外端口 LISTENING 到 HTTP 可用之间有 2.13–2.18 秒空窗，探端口会假失败。判断卡在哪层看报错是 000 还是 403。

这条适用于

  • Ollama 安装在 Windows 上（托盘程序 ollama app.exe 在跑）；Linux/macOS 无托盘回拉问题，第三层也不适用
  • 能执行 netstat / Get-NetFirewallApplicationFilter（查规则不需要管理员，加规则才需要）
  • 两台机器在同一网段且能互相 ping 通（跨网段/VPN 会让结论失真，本文未验证该情况）

版本指纹

Windows 11 专业版 / Ollama 0.40.4 / RTX 5090 D 32607 MiB（驱动 591.86 / CUDA 13.1）/ 对端 RTX 5060 Ti 16311 MiB / 防火墙三配置 Domain·Private·Public 均启用

具体做法

本机实测环境：Windows 11 / Ollama 0.40.4 / RTX 5090 D 32607 MiB / 对端 RTX 5060 Ti 16311 MiB（局域网另一台主机，同网段）/ 本机（私有网段地址）。

【第一层 绑定地址】
· 默认监听 127.0.0.1:11434；改 HKCU 后监听与 pid 均不变，证明注册表对已运行进程无效
· 对照组 A：显式给进程 OLLAMA_HOST=0.0.0.0:11434 → 监听 0.0.0.0:11434（绑定成功）
· 对照组 B：只改注册表 HKCU\Environment=0.0.0.0:11434，进程不显式设 → 监听仍 127.0.0.1:11434（失败）
· 托盘回拉：taskkill 服务进程后重新监听耗时 1.271 / 1.076 / 1.077 秒（三轮），pid 换了但环境变量仍是旧的
· 本机用局域网 IP 访问：code=200；从对端访问：code=000

【第二层 来源白名单（OLLAMA_ORIGINS）】
· 同地址同路径，只改 Origin 头：Origin 为本机 localhost:3000 → 200 OK + Access-Control-Allow-Origin: http://localhost:3000；Origin 设为对端局域网 IP:3000 → 403 Forbidden + Content-Length: 0（响应体无任何提示文字）
· 默认白名单 17 条：http/https + localhost / 127.0.0.1 / 0.0.0.0 各自的 :* 变体（12 条）+ app://* / file://* / tauri://* / vscode-webview://* / vscode-file://*（5 条）。局域网 IP 一条都没有
· 设 OLLAMA_ORIGINS=* 后：日志变 18 条，* 排首位，跨域请求返回 200 + Access-Control-Allow-Origin: *。是追加不是覆盖

【第三层 防火墙程序规则】
· 四端口同机对照（全部绑 0.0.0.0，从对端主机发起）：Ollama 11434 → code=000；Ollama 换端口 11438 → code=000；ComfyUI 8188 → code=200；python http.server 11437 → code=200
· 换端口无效说明不是端口问题。程序差异：python.exe 入站放行规则 4 条（Enabled=True），ollama.exe 0 条
· 三个配置文件（Domain/Private/Public）均启用，DefaultInboundAction 为 NotConfigured（即默认阻止）
· 需要管理员权限才能添加入站规则；普通权限下 netsh/route 均被拒
【启动空窗】
· 端口首次可连 / HTTP 首次可返回：0.223→2.394（空窗 2.178）、0.217→2.344（2.133）、0.217→2.370（2.161）秒
· 空窗成因：日志 discovering available GPUs... → inference compute ... name=CUDA0

【性能口径说明】
测试期间本机 GPU 有其他计算任务占用（nvidia-smi 利用率 100%、功耗约 600 W、可用显存最低 4409 MiB），故本文与本文数据不引用任何绝对吞吐，只引用与负载无关的结构性结果（监听地址、HTTP 状态码、规则条数、时序间隔）。注：正文示例中的局域网地址已做网段化处理，具体主机地址不入库。

失效边界
四点必须说清：① 防火墙结论在 Windows 11 上验证，Windows 10 / macOS / Linux 的默认策略不同（Linux 上 firewalld/ufw 往往是另一套判据），不能直接照搬 ② OLLAMA_ORIGINS=* 只适合纯内网；Ollama 无鉴权，任何能连上的人都能跑模型、读对话，公网必须靠反代加鉴权 ③ 启动空窗的 2.1 秒是 GPU 发现耗时，机器越快越短，但不会为零，探活逻辑必须按 HTTP 而非端口判断 ④ 从对端看到 code=000 也可能是本机与对端不在同一网段或被中间设备拦截，本文未验证这种情况，判断前三层时先确认两端能 ping 通且路由不经 VPN。
