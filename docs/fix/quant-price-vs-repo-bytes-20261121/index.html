厂商写「4bit 只要 4.9GB」，先数仓库分片再算余量

成本账 · BF16 19.319GB / 4bit 4.9GB / 3.94 倍未标注整理于 2026-11-21 有效期 permanent

SenseNova Loop-9B 官方口径是「4bit 权重约 4.9 GB、部署显存低至 10GB 以内」。核仓库：12 个 safetensors 合计 19,318,917,488 B = 19.319 GB = 17.992 GiB，safetensors.total 9,412,963,952 参，折 2.0524 字节/参（BF16 存档、16.42 bit 每参）。4.9 GB 反算是 4.164 bit 每参，两个数差 3.94 倍。对 5060Ti 16G（可用约 15.9 GiB）：4.9 GB = 4.563 GiB，减完剩 11.337 GiB 才是给上下文和运行时的真实预算；BF16 的 17.992 GiB 则差 2.092 GiB，权重都装不进。算法：可用显存 − 权重字节数 = 上下文预算，不是总显存 − 宣传数字。

具体做法

【仓库直读（HF API 2026-11-20 取）】
  12 个 safetensors 合计 19,318,917,488 B = 19.319 GB = 17.992 GiB
  safetensors.total = 9,412,963,952 参（BF16 9,409,812,208 + F32 3,151,744）
  → 19,318,917,488 × 8 ÷ 9,412,963,952 = 16.42 bit 每参 = 2.0524 字节/参
【官方口径（发布会转述）】
  4bit 权重约 4.9 GB；部署显存低至 10GB 以内；32 物理层循环 2 次展开成 56 次层计算；上下文 512K；Apache-2.0
  → 4.9e9 × 8 ÷ 9,412,963,952 = 4.164 bit 每参
  → 19.319 ÷ 4.9 = 3.94 倍
【5060Ti 16G 容量账（可用按 15.9 GiB 估）】
  4bit：4.9 GB = 4.563 GiB → 15.9 − 4.563 = 11.337 GiB 余量给上下文与运行时
  BF16：17.992 GiB → 差 2.092 GiB，权重装不进
【未取到】
  config.json 直连 gated（auto），逐层结构（循环层数 / 头数 / head_dim）无原值 → 512K 的 KV 缓存体积未计算
  model-00002.safetensors 仅 8,328 B，疑似占位片，12 片总和是否等于完整权重未逐片比对
【社区读数（2026-11-20）】
  HF downloads 1,447 / likes 391；许可证 Apache-2.0
失效边界
【口径边界】
1. 4.164 bit 每参是从官方「4.9 GB」反算出来的，属厂商口径换算，实际量化档位与分组方式未核。
2. 「部署显存低至 10GB 以内」对应的上下文长度厂商没说，本文不外推。10 GB 装 4.563 GiB 权重加短上下文很正常；装 512K 缓存从任何 9B 模型的量级看都不像，但这条是推理不是实测。
3. 模型未在本地下载运行，本篇零 tok/s，所有结论都是体积与算术，不含速度。
4. 5060Ti 的 15.9 GiB 是标称 16 GiB 扣驱动与显示占用的估算，驱动版本会让它浮动几百 MiB。
5. GB 为十进制、GiB 为二进制，19,318,917,488 B = 19.319 GB = 17.992 GiB，两者不可混用。
